# 拼多多自动找同款与采购价补全

本模块是Ozon找品任务与MuMu安卓模拟器之间的本地桥接层。它不使用拼多多官方API，而是控制用户已登录的拼多多App。

## 当前阶段（MVP 5.2）

- 导入已完成Ozon主图与核价的JSON。
- 只允许`pending_pinduoduo_search`任务进入模拟器阶段。
- 检查MuMu设备、安卓启动状态和拼多多安装状态。
- 将受信任的Ozon主图下载到本地运行目录，再下发到MuMu相册。
- 自动启动拼多多、按页面语义定位“拍照搜索”，在摄像头报错前快速选择最新主图。
- 自动读取当前屏以图搜结果中的候选标题和页面最低价；最低价只用于候选排序和参考，不再预填为采购成本。
- 当前屏候选中先核验最低价项，再按原显示顺序继续；单个详情失败自动重试一次，并继续往后处理，直到取得3个完整候选或当前屏候选用完。
- 完整候选会读取详情标题、详情展示价、商品ID、稳定链接、主图地址、优惠/限量标签和明确包邮信息，再返回搜索结果处理下一款。
- 详情字段改为分开保存：一旦取得商品ID就立即构造并保留稳定链接；标题、详情价或运费加载较慢时显示具体缺失字段，不再把已经取得的链接整条丢弃。
- 候选详情重试之间会清理残留购买弹窗，回到“搜图片同款”结果页后再继续；搜索结果标记消失前不接收详情路由，不同候选之间增加1.2–2.6秒随机缓冲，降低页面尚未切换完成造成的串读。
- 每个已核验候选在详情页额外保存一张本地证据截图；AI优先读取本地截图，缺失时使用受信任的拼多多详情缩略图。
- 当拼多多详情无障碍文本把价格与销量/件数连成一个数字时，会与同一候选的搜索页价格交叉校验；纠正后的价格用于展示，同时保留原始异常值和纠正原因。
- 支持一键批量串行处理全部待找款任务；已完成项自动跳过，单件失败不会中断后续任务。
- 支持“暂停、继续、停止”。暂停和停止会先让当前商品安全完成，再在下一件开始前生效。
- 队列、候选结果和批量游标逐件写入浏览器本地存储；页面刷新或电脑重启后重新打开本工具，可从未完成项继续。
- 每件商品完成后随机等待12–25秒再处理下一件；等待期间可暂停或停止。
- 页面新增“耗时埋点”面板：逐件保留主图下载、MuMu相册下发、拼多多页面、候选详情、证据图和重试等实际耗时，显示平均耗时与最慢阶段；用于后续提效，不改变当前风控间隔或核验范围。
- 首页、搜索结果和候选详情读取过程中持续检查实名认证、账号风险、安全验证及验证码页面；命中后保存当前游标并自动暂停，当前商品不会跳过，人工解除限制后可重试。
- 支持单件或批量调用阿里云百炼`qwen3.7-flash`，同时比较Ozon主图和前3个拼多多候选证据，输出推荐候选、置信度、规格冲突、逐候选差异和是否需要人工复核。
- 候选缩略图兼容拼多多官方`pddpic.com`与`yangkeduo.com`域名；单个候选图片读取失败时继续使用其余有效证据并强制人工复核，不再阻断整件商品。若全部候选图片均失败，商品行直接显示具体错误。
- AI同款判断置信度低于85、存在规格冲突或证据不足时强制保留人工复核，不进入规格实价自动核验。
- AI顶层“推荐同款”还必须与最佳候选的逐项结论、逐项置信度、关键差异和判断理由保持一致；出现型号、规格、数量、方向、套装、制式或TORX/Hex等矛盾时自动降级为人工复核。页面也会重新拦截本机旧队列中的矛盾判断。
- AI结果达到`same_product`、置信度不低于85且无需人工复核时，自动打开推荐候选详情并加入拼多多收藏；页面逐行显示“收藏中”“已收藏”“收藏失败”或“收藏暂停”，并统计已收藏数量。
- 自动收藏只点击详情页独立“收藏”控件，点击后必须重新读取到“已收藏”才记为成功；商品原本已收藏时不会重复点击。触发拼多多风控时批量AI与收藏立即停止，人工处理后可继续。
- 候选商品不再用普通网页链接打开；点击“在App打开”会通过本地Agent直接在MuMu已登录的拼多多App中打开对应详情，避免PC网页端登录与App账号冲突。批量流程运行期间该按钮自动禁用。
- 页面明确区分“未核验”“详情读取失败（已重试2次）”和“链接解析失败”，不再统一显示“链接未取得”。
- 明确同款会安全打开购买弹窗，结构化读取全部“规格名 + 常规标价”；`qwen3.7-flash`按Ozon图片、商品名、数量、方向、型号和套装内容选择目标规格，程序点击后必须读取到一致的“已选”回执才记为核验成功。
- 当前自动选择只处理单一规格维度；同时存在颜色、尺寸等多个维度时会保留全部选项并转人工复核，避免只选中其中一个维度后误读价格。
- MuMu页面结构读取偶发退出码137时自动重试最多2次；购买页打开但读不到规格时，将页面结构JSON和截图保存到`pinduoduo-agent/runtime/diagnostics`，用于区分单一规格、页面未加载和新布局解析失败。
- 规格核价不会点击“提交订单”；`多多支付余额`、券后提交价和多件折扣均视为账号或门槛优惠并忽略。只有商品明确包邮时才自动写入采购成本，运费未知会转人工复核。
- 历史18%成本上限只作快速初筛：目标规格采购价更高时直接淘汰，不再访问Ozon；价格不高于历史上限时，通过0.6.29扩展读取一次Ozon当前绿标、同源黑标、佣金和运费，重新计算最终成本上限。
- Ozon最终复价结果缓存30分钟；复价失败时保留已经确认的拼多多规格价，但利润结论保持未确认，不沿用旧上限冒充最终结论。
- 所有任务、图片和候选结果只保存在本机，不提交GitHub。

搜索页、详情页最低展示价或AI推荐仍不会直接认定为采购成本；只有规格弹窗实价核验成功或人工明确确认后，才进入条件式Ozon最终复价。

## 配置千问

1. 在阿里云百炼创建API Key。
2. 双击项目根目录的`配置千问API密钥.cmd`，在黑色窗口中输入密钥；输入内容不会显示。
3. 密钥使用当前Windows账户的DPAPI加密后保存到本机`pinduoduo-agent/runtime`，该目录不会提交GitHub。
4. 重新打开本工具；右上角显示`qwen3.7-flash已配置`后即可使用“AI判断”或“批量AI判断同款”。

如果系统已通过`DASHSCOPE_API_KEY`环境变量配置密钥，会优先使用该环境变量。可用`QWEN_MODEL`环境变量覆盖默认模型，但当前正式默认值固定为`qwen3.7-flash`。

## 启动

双击项目根目录的`启动拼多多找品Agent.cmd`。工具会打开：

```text
http://127.0.0.1:17628/
```

若MuMu未启动，先点击“启动模拟器”，等安卓桌面出现后点击“检查模拟器”。导入JSON后先点击“批量自动找同款”，再点击“批量AI判断同款”。明确推荐项会自动收藏并尝试规格实价核验；历史任务可点击“批量核验规格价与最终复价”。最终复价依赖已重新加载的0.6.29浏览器扩展。

## 采购价定义

拼多多采购价按目标规格的常规单件成交价记录，不计账号余额、特定支付方式、新客券或多件门槛优惠。商品明确包邮时运费为0；如果页面另有运费，必须把运费加到规格价后再写入采购成本。
