# 商品池批量操作实施计划

**目标：** V1.35 / 0.6.54，减少商品池逐行保存和淘汰操作。

**范围：** 当前页勾选与全选、批量保存已修改的状态/备注、确认后批量淘汰、固定表头/勾选与商品列/操作列、保留筛选及翻页草稿和列表滚动位置。批量淘汰保留历史和备注，不删除核价或扫描记录；不通过批量操作把未复核商品标记为已复核。原单品核价及自动下一件逻辑不变。

**实现约定：** 批量请求 `changes` 为 `{sku,patch:{status,notes},expected:{status,notes,blocked,manualSavedAt}}[]`，共享核心 `updateProducts(state,changes,now?)` 一次校验和生成新状态，重复 SKU、未知商品、非法状态、新批量已复核、过时状态全部拒绝；不部分写入。工作台使用原云端 revision 写入；独立版使用原串行本地存储。只在确认持久化后清除对应草稿和勾选，失败保留重试。全选仅当前页；切换筛选和页码清除勾选但保留草稿。

- [x] 共享核心：补充多 SKU、拒绝部分成功、禁止新批量复核及冲突测试；两版同步同一核心。
- [x] 独立版：本地消息处理、勾选与工具栏、草稿和反馈；核价面板状态操作与批量操作不得并发。验证本地存储与独立包。
- [x] 工作台：同账户、revision、批量写入 API 测试；商品池勾选、草稿、操作与滚动布局；保持快速核价工作流。
- [x] 全量测试、构建、双版发布与记录；双版模拟 Chromium UI 验证通过，不使用真实业务数据执行批量写入。
